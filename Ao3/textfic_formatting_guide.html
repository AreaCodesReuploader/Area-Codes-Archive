Text-Fic Formatting Guide

This chapter explains how to format the text-message portions of this fic during the AO3 reupload. It is intended as a reference for anyone helping transfer, edit, or proofread chapters.

The work uses an AO3 work skin to create left- and right-aligned message bubbles. The HTML classes determine how each message appears.

Paste chapter formatting into AO3 using the HTML editor, not the Rich Text editor. Always use AO3's Preview function before posting.

Important orientation rule

  • Incoming messages appear on the left.
  • Outgoing messages appear on the right.
  • Incoming messages are messages received by the owner of the phone being shown.
  • Outgoing messages are messages sent by the owner of the phone being shown.

Do not decide the direction based on which character is more important. Decide it based on whose phone or point of view the conversation is being displayed from.

1. The basic conversation wrapper

Every text conversation must be placed inside a container using the textfic class.

The contact name may be shown at the top using the contact-name class.

Rendered example

Unknown Number

This is an incoming message.

This is an outgoing message.

HTML used

<div class="textfic">

  <p class="contact-name">Unknown Number</p>

  <div class="message incoming">
    <p class="bubble">This is an incoming message.</p>
  </div>

  <div class="message outgoing">
    <p class="bubble">This is an outgoing message.</p>
  </div>

</div>

2. Incoming messages

Incoming messages use both the message and incoming classes. They appear on the left side and use the light-gray bubble.

Rendered example

if you don't wake up in the next ten minutes, I'll kill you

HTML used

<div class="message incoming">
  <p class="bubble">if you don't wake up in the next ten minutes, I'll kill you</p>
</div>

3. Outgoing messages

Outgoing messages use both the message and outgoing classes. They appear on the right side.

Rendered example

it's 3 in the afternoon ???

HTML used

<div class="message outgoing">
  <p class="bubble">it's 3 in the afternoon ???</p>
</div>

4. Separate messages need separate wrappers

Every individual text message should have its own message wrapper and its own bubble.

Do not combine multiple separate texts into one bubble merely because the same person sent them.

Rendered example

oh wait fuck

shit you're not nick

can confirm. i am not nick.

HTML used

<div class="message incoming">
  <p class="bubble">oh wait fuck</p>
</div>

<div class="message incoming">
  <p class="bubble">shit you're not nick</p>
</div>

<div class="message outgoing">
  <p class="bubble">can confirm. i am not nick.</p>
</div>

5. Contact names

Use contact-name near the top of a conversation to show the name saved in the phone.

Before a character has been saved as a contact, use something like Unknown Number, Unknown Caller, or the visible phone number if the original includes it.

Rendered example

Unknown Number

who even are you lol

HTML used

<p class="contact-name">Unknown Number</p>

After the phone owner saves the contact, change only the visible text: 

<p class="contact-name">Kalliope</p>

6. Sender labels

Use the sender class when a sender's name needs to appear above a message. This is most useful for group chats, multiple unknown numbers, or any screen where the sender would otherwise be unclear.

Rendered example

Unknown Number

This message has a sender label.

HTML used

<div class="message incoming">
  <p class="sender">Unknown Number</p>
  <p class="bubble">This message has a sender label.</p>
</div>

Sender labels are optional in one-on-one conversations. When several messages from the same person appear consecutively, the label does not have to be repeated above every bubble.

7. Bold, italics, and underlining

Use <strong> for bold text, <em> for italic text, and <u> for underlined text.

Rendered example

This has bold text, italic text, and underlined text.

This is bold, italic, and underlined.

HTML used

<div class="message incoming">
  <p class="bubble">
    This has <strong>bold text</strong>,
    <em>italic text</em>, and
    <u>underlined text</u>.
  </p>
</div>

<div class="message outgoing">
  <p class="bubble">
    This is <strong><em><u>bold, italic, and underlined</u></em></strong>.
  </p>
</div>

Nested tags must close in reverse order.

Correct:

<strong><em><u>text</u></em></strong>

8. Emojis

Ordinary Unicode emojis can be pasted directly into a message. They do not need a special class or an image file.

Rendered example

what are you doing 😭

nothing suspicious 👍

sure 💀💀💀

HTML used

<div class="message incoming">
  <p class="bubble">what are you doing 😭</p>
</div>

<div class="message outgoing">
  <p class="bubble">nothing suspicious 👍</p>
</div>

<div class="message incoming">
  <p class="bubble">sure 💀💀💀</p>
</div>

Preserve the exact emoji and number of repeated emojis used in the archived chapter. Emojis may look slightly different on different devices because each operating system uses its own emoji artwork.

9. Line breaks inside one message

Use <br /> when text belongs in one message bubble but needs to continue on a new line.

Rendered example

I have two questions.
First, why are you awake?
Second, why did you answer?

HTML used

<div class="message incoming">
  <p class="bubble">
    I have two questions.<br />
    First, why are you awake?<br />
    Second, why did you answer?
  </p>
</div>

Use separate message wrappers instead when the original fic shows separate texts.

10. Date and time dividers

Use chat-date for a centered date, day, time, or major conversation break.

Rendered example

Today, 3:02 PM

are you awake?

Later that evening

unfortunately

HTML used

<p class="chat-date">Today, 3:02 PM</p>

<div class="message incoming">
  <p class="bubble">are you awake?</p>
</div>

<p class="chat-date">Later that evening</p>

Do not invent timestamps or dates that were not present in the archived version unless the reupload team intentionally decides to add them.

11. Message timestamps, delivery status, and read receipts

Use message-time for a timestamp, message-status for a standalone status, or message-meta for a combined time and status.

Rendered example

This message has a timestamp.

3:14 PM

This message has been delivered.

Delivered

This message has been read.

Read 3:19 PM

HTML used

<div class="message incoming">
  <p class="bubble">This message has a timestamp.</p>
  <p class="message-time">3:14 PM</p>
</div>

<div class="message outgoing">
  <p class="bubble">This message has been delivered.</p>
  <p class="message-status">Delivered</p>
</div>

<div class="message outgoing">
  <p class="bubble">This message has been read.</p>
  <p class="message-meta">Read 3:19 PM</p>
</div>

Delivery and read receipts normally belong beneath outgoing messages because they report the status of a message sent by the phone owner.

12. Typing indicators

Use the typing class in addition to bubble.

Rendered example

•••

HTML used

<div class="message incoming">
  <p class="bubble typing">•••</p>
</div>

13. System messages

Use system-message for interface information that is not dialogue, such as missed calls, deleted messages, contact-name changes, group-chat events, or shared locations.

Rendered example

Missed voice call

You changed the contact name to Nick.

A message was deleted.

HTML used

<p class="system-message">Missed voice call</p>
<p class="system-message">You changed the contact name to Nick.</p>
<p class="system-message">A message was deleted.</p>

14. Images hosted on GitHub

Images are stored in the reupload's GitHub repository and embedded into AO3 using an <img> tag.

The value of src must be a URL that opens the image itself. Do not use the ordinary GitHub repository page URL containing /blob/, because that opens a GitHub webpage rather than directly serving the image.

Use the repository file's Raw URL, which normally begins with: 

https://raw.githubusercontent.com/USERNAME/REPOSITORY/BRANCH/path/to/image.jpg

Replace USERNAME, REPOSITORY, BRANCH, and the file path with the real values.

Example:

https://raw.githubusercontent.com/example-user/area-codes-archive/main/images/chapter-04/nick-asleep.jpg

Keep the GitHub repository public while the images are embedded in the AO3 work. Renaming, moving, or deleting an image in GitHub will break the old URL unless every AO3 chapter using it is updated.

15. Image-only messages

Use image-message on the message wrapper, image-bubble on the bubble container, and message-image on the image itself.

Rendered example

HTML used

<div class="message incoming image-message">
  <div class="bubble image-bubble">
    <img
      class="message-image"
      src="https://raw.githubusercontent.com/USERNAME/REPOSITORY/main/images/example.jpg"
      alt="Example image sent in a text conversation."
    />
  </div>
</div>

Change incoming to outgoing when the phone owner sent the image.

16. Image alternative text

Every image must include an alt attribute. The alternative text explains the image for screen-reader users and appears if the image cannot load.

Good:

alt="Nick asleep face-down across a couch with one shoe still on."

Too vague:

alt="image"

Describe information that matters to the scene. Do not include phrases such as “image of” or “picture of” unless that distinction is narratively important.

If an image contains important visible text, include that text in the alternative description: 

alt="Screenshot of a message reading: Nick, answer your phone before I drive to Houston myself."

17. Image with a caption in the same bubble

Use image-caption when text appears directly beneath the image inside the same message bubble.

Rendered example

this is the idiot in question

HTML used

<div class="message incoming image-message">
  <div class="bubble image-bubble">
    <img
      class="message-image"
      src="https://raw.githubusercontent.com/USERNAME/REPOSITORY/main/images/nick-asleep.jpg"
      alt="Nick asleep face-down across a couch with one shoe still on."
    />
    <p class="image-caption">this is the idiot in question</p>
  </div>
</div>

18. Image followed by a separate text message

When the archived fic shows an image message and then a separate text, use two separate message wrappers.

Rendered example

this is the idiot in question

HTML used

<div class="message incoming image-message">
  <div class="bubble image-bubble">
    <img
      class="message-image"
      src="https://raw.githubusercontent.com/USERNAME/REPOSITORY/main/images/nick-asleep.jpg"
      alt="Nick asleep face-down across a couch with one shoe still on."
    />
  </div>
</div>

<div class="message incoming">
  <p class="bubble">this is the idiot in question</p>
</div>

19. Image with a timestamp or receipt

Rendered example

4:52 PM · Delivered

HTML used

<div class="message outgoing image-message">
  <div class="bubble image-bubble">
    <img
      class="message-image"
      src="https://raw.githubusercontent.com/USERNAME/REPOSITORY/main/images/florida-rain.jpg"
      alt="A palm tree bending sideways in heavy rain."
    />
  </div>
  <p class="message-meta">4:52 PM · Delivered</p>
</div>

20. Multiple images in one message

Use image-stack when multiple images were sent as one grouped message. Stacking is the safest layout across screen sizes and custom AO3 site skins.

Rendered example

HTML used

<div class="message incoming image-message">
  <div class="bubble image-bubble image-stack">
    <img
      class="message-image"
      src="https://raw.githubusercontent.com/USERNAME/REPOSITORY/main/images/coffee-before.jpg"
      alt="Nick holding an enormous iced coffee."
    />

    <img
      class="message-image"
      src="https://raw.githubusercontent.com/USERNAME/REPOSITORY/main/images/coffee-after.jpg"
      alt="The iced coffee spilled across a car seat."
    />
  </div>
</div>

Use one alt description per image.

21. Visible image transcripts

Use image-transcript when an image contains substantial text that should also be available visibly beneath it. This is especially useful for screenshots, handwritten notes, memes whose wording matters, and social-media posts.

Rendered example

Image transcript: Nick, answer your phone before I drive to Houston myself.

HTML used

<div class="message incoming image-message">
  <div class="bubble image-bubble">
    <img
      class="message-image"
      src="https://raw.githubusercontent.com/USERNAME/REPOSITORY/main/images/message-screenshot.jpg"
      alt="Screenshot of a message from Nick."
    />
  </div>
</div>

<p class="image-transcript">
  <strong>Image transcript:</strong>
  Nick, answer your phone before I drive to Houston myself.
</p>

22. Group chats

Use contact-name for the group-chat name and sender above incoming messages so readers know which participant sent each one.

Rendered example

Group Chat: Bad Decisions

Nick

Who added the unknown number?

Unknown Number

I invited myself 😌

Please stop encouraging her.

Nick

No.

HTML used

<div class="textfic">
  <p class="contact-name">Group Chat: Bad Decisions</p>

  <div class="message incoming">
    <p class="sender">Nick</p>
    <p class="bubble">Who added the unknown number?</p>
  </div>

  <div class="message incoming">
    <p class="sender">Unknown Number</p>
    <p class="bubble">I invited myself 😌</p>
  </div>

  <div class="message outgoing">
    <p class="bubble">Please stop encouraging her.</p>
  </div>
</div>

23. Quick class reference

Class Purpose
textfic Wraps the entire text conversation.
contact-name Displays the contact name or group-chat name.
chat-date Displays a centered date, day, time, or conversation divider.
message Wraps one individual message and any metadata belonging to it.
incoming Places a received message on the left.
outgoing Places a sent message on the right.
sender Shows the sender's name above a message.
bubble Creates the visible message bubble.
message-time Shows a timestamp beneath a message.
message-status Shows a status such as Delivered, Read, Sent, or Not Delivered.
message-meta Shows a combined timestamp and status on one line.
system-message Displays centered interface information that is not dialogue.
typing Styles a bubble as a typing indicator.
image-message Allows a message containing an image to use the image-message sizing rules.
image-bubble Adjusts padding and overflow for a bubble containing an image.
message-image Makes an embedded image scale safely inside its bubble.
image-caption Displays text directly beneath an image inside the same bubble.
image-stack Formats multiple images stacked inside one message.
image-transcript Displays a visible transcript or description beneath an image.

24. HTML tag reference

Visible HTML Purpose
&lt;strong&gt;text&lt;/strong&gt; Creates bold text.
&lt;em&gt;text&lt;/em&gt; Creates italic text.
&lt;u&gt;text&lt;/u&gt; Creates underlined text.
&lt;br /&gt; Creates a new line inside the same bubble.
&lt;p&gt;text&lt;/p&gt; Creates a paragraph.
&lt;div&gt;...&lt;/div&gt; Creates a structural container.
&lt;img src="URL" alt="Description" /&gt; Embeds an externally hosted image.

25. GitHub image-file organization

Keep image filenames descriptive, stable, and unique. A recommended structure is: 

images/
  chapter-001/
    ch001-msg001-wrong-number-profile.jpg
    ch001-msg042-nick-asleep.jpg
  chapter-002/
    ch002-msg018-reaction-image.png

Recommended filename pattern: 

chCHAPTER-msgMESSAGE-short-description.extension

Examples: 

ch004-msg017-nick-asleep.jpg
ch011-msg063-weather-screenshot.png
ch023-msg004-reaction-meme.gif

Avoid spaces, punctuation, and vague names such as image1.jpg. Use lowercase letters, numbers, and hyphens.

Keep a local backup of the repository and the original archived files. GitHub is the live host used by AO3, but it should not be the only surviving copy.

26. Common mistakes

Using a GitHub webpage URL instead of the image URL

Wrong:

https://github.com/USERNAME/REPOSITORY/blob/main/images/example.jpg

Correct raw-file form:

https://raw.githubusercontent.com/USERNAME/REPOSITORY/main/images/example.jpg

Forgetting alternative text

Wrong:

<img class="message-image" src="IMAGE-URL" />

Correct:

<img
  class="message-image"
  src="IMAGE-URL"
  alt="A concise description of the image and any important visible text."
/>

Putting incoming messages on the wrong side

  • incoming means received by the phone owner and appears on the left.
  • outgoing means sent by the phone owner and appears on the right.

Forgetting the bubble class

Wrong:

<div class="message incoming">
  <p>This will not have bubble styling.</p>
</div>

Correct:

<div class="message incoming">
  <p class="bubble">This will have bubble styling.</p>
</div>

Putting multiple separate texts in one bubble

If the archive shows separate messages, each message needs its own wrapper.

Accidentally changing the text

Preserve original capitalization, spelling, punctuation, spacing, emphasis, emojis, and deliberate typos. Something that looks like a mistake may be part of the character's texting style.

Obvious transfer errors, such as two messages being accidentally joined together, should be checked against the archived Wattpad chapter before correction.

Renaming or moving an image after posting

Changing a GitHub filename or folder path changes its URL. Update every AO3 chapter using that URL or leave the original file in place.

27. Reupload workflow

  1. Open the archived Wattpad chapter.
  2. Identify which character owns the phone or viewpoint being displayed.
  3. Mark received messages as incoming.
  4. Mark sent messages as outgoing.
  5. Give every separate text its own message wrapper.
  6. Preserve bold, italics, underlining, capitalization, punctuation, and emojis.
  7. Download and preserve every image from the archive.
  8. Give each image a stable descriptive filename.
  9. Add the image to the correct GitHub repository folder.
  10. Use the image's raw GitHub URL in the AO3 src attribute.
  11. Write meaningful alt text.
  12. Add contact names, timestamps, receipts, and system messages only where appropriate.
  13. Paste the chapter into AO3 using the HTML editor.
  14. Preview the chapter before posting.
  15. Check text and images in both a light and dark AO3 site skin.
  16. Check the chapter at a narrow or mobile-sized width.
  17. Open each embedded image to confirm the URL works while logged out of GitHub.

30. Final checklist

  • Is the entire conversation inside <div class="textfic">?
  • Are incoming messages on the left?
  • Are outgoing messages on the right?
  • Does every separate text have its own wrapper?
  • Does every text message include class="bubble"?
  • Were the original bold, italic, and underlined sections preserved?
  • Were all original emojis preserved exactly?
  • Were intentional capitalization, spelling, and punctuation preserved?
  • Are timestamps and receipts included only where appropriate?
  • Does every image use a working raw GitHub URL?
  • Does every image include meaningful alt text?
  • Were image captions kept inside or outside the bubble according to the archive?
  • Were grouped images kept together?
  • Are all opening tags properly closed?
  • Was the chapter pasted into AO3's HTML editor?
  • Was the final result checked using Preview?
  • Is incoming text readable in both light and dark site skins?
  • Do all images scale correctly on a narrow screen?
